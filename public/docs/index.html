Introduction

Ajisai is an AI-first, vector-oriented dataflow language. A program is a sequence of words: values are pushed onto a single stack, and each word consumes operands from the stack and pushes its results. Every number is exact — exact rationals and the algebraic SQRT closure over them, carried in a multiquadratic normal form — so arithmetic and comparison both work without rounding. A number's continued-fraction form is a canonical display derived from the value, not its internal storage.

This reference introduces each feature with short, verified examples. Every example has an "Open in Playground" button; pressing it loads the code into the app's editor so you can run it and see how it behaves.

The Reference is for using Ajisai. If you are implementing or porting the language, the single design authority is the Specification; this page is derived from it for learners and day-to-day users.

How to read the examples

The Expected value column shows the final stack exactly as the language renders it, value by value. Two display conventions matter from the start:

Numbers display as exact fractions in numerator/denominator form — the integer three renders as 3/1. Truth values display as TRUE and FALSE; the absence of a value displays as NIL.

That is the Stack area's standard rendering, and it is what this reference's Expected value column shows. The Stack area also carries a LaTeX checkbox — off by default — that redraws the same values as typeset mathematics: a fraction becomes a stacked fraction, a numeric vector becomes a matrix, and a denominator of one reads as a plain integer, so 3/1 is drawn as 3. That is a second reading of one value, not a second value: the number is the same exact rational either way, nothing is rounded or reduced, and unchecking the box brings the canonical form back. A value with no faithful mathematical reading — a string, NIL, a ragged vector — stays in the standard rendering even with the box checked.

A collection can hold far more elements than are worth drawing, so the Stack area draws a leading part of a large one and ends it with a marker such as … 199900 more. The marker is a statement about the drawing, never about the value: the collection on the stack is complete, every word still sees all of it, and LENGTH reports the real length.

In the text of this reference, anything with a gray background is an Ajisai token. Every symbol token defined by Ajisai is a word in disguise — + is ADD and ^ is VENT — so the gray background is the signal that a mark belongs to the program, not to the prose.

Tokens and Spelling

A program is a sequence of tokens separated by whitespace. A token ends at exactly three things: whitespace, a structural delimiter ([ ] { } ( )), or the start of a comment (# to the end of the line). Nothing else ends a token, so every other character — punctuation included — is an ordinary name character.

The practical consequence is that an operator needs a space around it the same way a word does. 2 + is two tokens; 2+ is a single name that no word answers to, and it fails as an unknown word rather than silently parsing as addition. Brackets and braces are the exception, because they delimit themselves: [ 1 2 ]LENGTH is read exactly like the spaced form, and so is a bracket written flush against another bracket.

A symbol obeys the rule a word obeys because a symbol is a name — one spelled with punctuation. Most are a single character, and the comparison family adds three of two: <=, >= and !=, for LTE, GTE and NEQ. That costs the rule above nothing, because a token ends only at whitespace or a delimiter and never in the middle. What a token means is decided by the whole token, not by its first character: 1/2 is a number because the entire lexeme parses as one, and a bare / is a name for the same reason.

Comments

A # begins a comment that runs to the end of the line, and the line's remaining characters are dropped before anything is tokenized. A # inside a string is ordinary text, so 'a # b' is one three-word string.

WrittenRead asWhy
3 4 +three tokensWhitespace ends each token; + is the symbol for ADD.
3 4+two tokens4+ is one name — an error, not addition.

Where a line break matters

Whitespace is whitespace: a newline separates tokens exactly as a space does, and a program may be laid out over as many lines as you like. There is one exception, and it is worth knowing before you meet it. A COND guard clause — a block containing a top-level | — must start its own line, and at most one such clause may begin on any line. Writing a whole COND on one line is a source error, not a style choice, and the message says so: COND: | clauses must be written one clause per line. See Conditionals. Nothing else in the language reads line breaks.

Number literals

A decimal literal carries at least one digit on both sides of the point: 0.5 and 5.0 are numbers, while .5 and 5. are not. The point is therefore never the first or last character of a number, which is what lets a lone . be an ordinary name rather than a truncated literal.

A string closes on the quote that sits at a token boundary, which is how a string carries an apostrophe with no escape character: 'It's fine' is one string. A quote followed immediately by a name character stays inside the text, so 'abc'CHARS is an unclosed string rather than two tokens.

Stack and Modifiers

Words take their operands from the stack and push their results back. Consumption is the default: a word eats the operands it reads. The single modifier, written before a word, is the one explicit way to change that:

ModifierEffect
KEEPRetain the operands of the next word and push its result as well.

KEEP prefixes the next word only, and it carries no symbol — it is written out. That is the whole modifier system: one explicit operation for the non-default behavior, and no Forth-style stack shufflers to go with it. Everything else about how a word behaves is in the word itself, so reading a call means reading a name and at most one prefix.

Arithmetic

The arithmetic words act element-wise between vectors, and a one-element vector broadcasts across a longer one. Each word has a canonical English name; the symbol is sugar:

Broadcasting is a rule about axes, not only about one-element vectors. Two vectors are paired axis by axis starting from the innermost, an axis the shorter one does not reach counts as length 1, and an axis of length 1 is reused across the other side's length — so [ 1 2 3 ] [ 10 ] * is [ 10/1 20/1 30/1 ] and [ [ 1 2 ] [ 3 4 ] ] [ 10 20 ] * is [ [ 10/1 40/1 ] [ 30/1 80/1 ] ]. Anything else is an error: [ 1 2 3 ] [ 10 20 ] * cannot pair 3 with 2. A scalar needs no axes and combines with every element however the vector is nested, ragged ones included; two vectors can only broadcast when both are rectangular.

NIL and the Bubble Rule

The failure model in one line: could not produce a value → a bubble; used incorrectly → an error. A well-formed operation that cannot produce a result projects onto NIL — a "bubble" carrying a structured reason — while malformed use (wrong types, missing operands) raises an ordinary error.

Bubbles flow: arithmetic and comparison are NIL-passthrough, so a NIL operand makes the result NIL without crashing the pipeline. Two words look at a bubble without disturbing it — NIL? asks whether the top value is one, and NIL-REASON reads the reason it carries. Both leave the value in place and push the answer above it. At the end, VENT (^) supplies a fallback.

What a block sees

A block has no stack discipline of its own. The word that evaluates it decides what the block can reach and what it may leave behind, and reading the wrong rule is the difference between a + inside the block finding two operands and finding none. There are five rules, and the block's own text does not say which applies to it — the word receiving it does.

Evaluated byThe block seesThe block leaves
A word body (DEF)the whole stackwhatever it pushes, however many
EXECthe whole stackwhatever it pushes, however many
COND guard, and the body that firesone value: the dispatch value, aloneexactly one — the top; leaving none is an error, and anything under the top is discarded
MAP FILTER ANY ALLone value: the current element, aloneexactly one — the mapped element, or a truth value for the predicate words
FOLDtwo values: the accumulator, then the elementexactly one: the next accumulator

So { + } 'ADDW' DEF followed by 3 4 ADDW gives 7, and so does 3 4 { + } EXEC — both see the whole stack. But 100 [ 1 2 ] { + } MAP is a stack underflow: the block sees one element and the 100 is not in its frame.

A block written inside another block is data where it is written. It is evaluated only when the word that receives it runs it, under that word's row above rather than the enclosing block's — which is why a word may call itself from inside a { } it hands to MAP or EXEC, and why that call is an ordinary recursive call.

Writing a word that takes two arguments

Ajisai has no DUP, SWAP, DROP or ROT, and that is deliberate rather than missing: several values travel in a vector, not on the stack. A word that needs two arguments takes one vector of two, and the caller either writes it — [ 3 4 ] — or builds it from computed values with COLLECT.

When you do need a position rather than a reduction, read it with GET: [ 0 ] GET is the first element and [ -1 ] GET the last, so { SORT [ -1 ] GET } 'PMAX' DEF answers the larger of a pair. REVERSE is the vector's swap, and TAKE with CONCAT rebuilds a vector from slices of one.

The one duplication device is KEEP. Prefixed to a word that reads one value and pushes one, it leaves the operand underneath the result, so KEEP REVERSE REVERSE is a two-line way to write "copy the vector on top". Prefixed to a two-operand word it keeps both operands, which is rarely what you want: [ 10 3 ] KEEP [ 0 ] GET leaves the index vector on the stack as well.

Code as data

A code block and a vector are different kinds of value: a vector is data and is never executable, and EXEC accepts only a code block. REFLECT is the one crossing between them. It turns a code block into a canonical vector of token records — and turns that vector back into the block — without evaluating anything and without consulting the dictionary.

Putting a runtime value inside a block

A block is source, so a value you computed while the program was running is not in it. MAP and FILTER take a block and nothing else, which raises a real question: how do you filter by a threshold you only learn at run time? { 5 LT } tests against a literal five, and there is no five to write when the number came out of the program.

REFLECT answers it in both directions. Build the token records for the block you want — with the runtime value converted to its lexeme by STR — and cross back into a block with REFLECT. The result is an ordinary block, and every word that takes one accepts it.

Sample codeExpected valueNotes
[ 3 1 4 1 5 9 2 6 ] 'AJISAI-CODE-1' 'number' 5 STR 2 COLLECT 'symbol' 'LT' 2 COLLECT 3 COLLECT REFLECT FILTER [ 3/1 1/1 4/1 1/1 2/1 ] The 5 is an ordinary stack value here; replace it with anything the program computed and the predicate follows.
Open in Playground

Read the middle line as the vector [ 'AJISAI-CODE-1' [ 'number' '5' ] [ 'symbol' 'LT' ] ] assembled a piece at a time: 2 COLLECT packs each two-element record, and the final 3 COLLECT packs the tag and the two records. This is the whole of partial application in Ajisai — there is no separate word for it, and none is needed, because a block is a value whose contents you can compute.

Conditionals

COND evaluates guard-and-body clauses in order and executes the body of the first guard that is true. In the clause form, | separates the guard from the body and each clause occupies exactly one line; TRUE makes an always-true else guard.

The else clause can also be spelled IDLE, and that is the spelling to prefer. IDLE is not one of the 57 Words and you will not find it in the Dictionary panel: it is a keyword read positionally, meaningful only as a guard, and it means this clause fires when no earlier one did. TRUE reaches the same outcome by pushing a value the guard then reads, which works but says less; IDLE says which clause is the fallback.

Sample codeExpected valueNotes
[ 0 ] { [ 0 ] < | 'negative' } { [ 0 ] = | 'zero' } { TRUE | 'positive' } COND 'zero' Clause form: guard left of |, body right; one clause per line.
Open in Playground
Sample codeExpected valueNotes
[ -5 ] { [ 0 ] < } { 'negative' } { TRUE } { 'positive' } COND 'negative' Pair form: alternating guard and body blocks.
Open in Playground

Each guard answers TRUE or FALSE, so a clause either fires or does not. If no clause matches and no else clause is present, COND raises an error.

One clause per line is a rule, not a layout preference — it is the only place in the language where a line break is significant (see Tokens and Spelling). Collapsing the clause form onto one line fails before anything runs, with COND: | clauses must be written one clause per line. The pair form above has no | in it and so carries no such rule: it fits on one line.

What a clause sees

A COND clause does not run on the stack you can see. Every guard, and the body of the clause that fires, runs in an isolated frame holding exactly one value — the value COND is dispatching on — and exactly one value comes back out of it: whatever is on top when the body finishes. This is different from a word body or EXEC, which see the whole stack; see What a block sees for all five rules side by side.

Two consequences are worth writing down before you meet them. A clause body cannot reach values that were on the stack before the COND: 1 2 3 4 followed by a clause whose body is + is a stack underflow, because + finds only the dispatch value. And a body that ends with several values keeps only the top one — { TRUE | 7 8 9 } answers 9, and the 7 and 8 go with the frame.

The isolation is what makes recursion over COND practical. A clause body that builds working values on its way to a self-call does not have to clean them up: they cannot survive the frame, so each turn of the recursion starts from one value no matter how much scaffolding the previous turn built.

Strings

A string is quoted with ' and shows in quotes on the stack. Those quotes are a display affordance, not part of the value: PRINT writes the raw text ('TEST' prints as TEST — see Output), while a string nested in a collection keeps its quotes ([ 'AB' 'CD' ] stays [ 'AB' 'CD' ]). Strings convert to and from numbers and characters with the cast words.

A string is one of the six value domains, not a vector of code points: 'A' [ 65 ] EQ is FALSE, and arithmetic on a string is an error rather than arithmetic on its codes. The empty string '' is an ordinary string, not NIL.

Because a string is not a vector, the collection words do not take one. LENGTH, GET, REVERSE and CONCAT all raise an error on a string; cross into the vector domain with CHARS first ('abc' CHARS LENGTH is 3). Concatenation is JOIN, which is the word for turning a vector of strings into one string: [ 'ab' 'cd' ] JOIN is 'abcd'. To join values you computed rather than wrote, gather them with COLLECT first — 'a' 'b' 2 COLLECT JOIN.

What DEF checks, and what it does not

DEF stores the body; it does not resolve the names inside it. A definition whose body calls a word that does not exist is accepted and reported as defined, and the failure surfaces the first time the word is called: { TOTALL 1 } 'FOO' DEF succeeds, and only running FOO reports Unknown word: TOTALL.

This is a design choice rather than a missing check. Names resolve at call time, which is exactly what lets one word call another that is defined after it — so a pair of words may call each other, and a definition never has to be ordered around its dependencies.

The cost is that a mistyped name in a body sits quietly until something calls it. The headless CLI is where that is caught ahead of time: ajisai check resolves every name in a file without executing anything and reports the unknown ones, and ajisai check --contract additionally verifies declared word contracts. The Playground has no equivalent — in the app, calling the word is the check.

Managing words

DEL deletes a user word by quoted name. Dependencies are tracked: a word that other words depend on cannot be deleted at all, so a dangling reference is impossible — delete the dependents first.

Word names are case-insensitive (add10 and ADD10 are the same word) and conventionally follow an action-object style such as APPLY-GAIN. How a name is matched to a definition is the subject of Dictionaries and Word Identity.

Dictionaries and Word Identity

The dictionary has two tiers, and those two are the whole of it. Core holds the 57 canonical words and is sealed: a Core name cannot be redefined or deleted. User holds everything you define with DEF.

Those 57 words divide into a 35-word Semantic Kernel and 22 Standard words. The Kernel words are the ones that build or observe a kind of value, or that are the single explicit way to do something — run a code block, recover from a NIL, change the dictionary, print, cross between code and data. The Standard words give a frequent idea one fixed name and contract: SUB, MIN, SORT, MAP, TRIM and the rest. The division tells you where a word sits in the design; it changes nothing about how you use one. All 57 are ordinary Core words in the same flat dictionary, reached by their plain names, with the same contracts, examples, and error conditions. Each word's tier is listed in the Word Reference and reported by LOOKUP.

A name resolves in Core or in User, and User never shadows Core. A word's name is therefore its whole address — there is no qualified form, no dictionary to select, and no way for a bare name to be ambiguous. Names are case-insensitive, so add10 and ADD10 are the same word.

Sample codeExpected valueNotes
{ 10 ADD } 'ADD10' DEF 5 ADD10 15/1 A defined word is reached by its name.
{ 1 } 'ADD' DEF error Core is sealed, so a Core name cannot be taken.
{ 10 ADD } 'ADD10' DEF { 20 ADD } 'ADD10' DEF 5 ADD10 25/1 A redefinition rebinds the one User entry — unless another word depends on it, which DEF refuses.

Word identity

Every word has a content identity: a digest over its normalized definition and the identities of the words it calls. Two definitions with the same identity are the same word, whatever they are named, and changing a definition changes the identity of everything that depends on it. That is what makes DEF and DEL refuse to disturb a word something else still references — the dependency is on the word, not on the spelling.

Output

PRINT writes the top stack value to the output area. Like any word it consumes its operand by default; with KEEP the value also stays on the stack. The Playground always shows the final stack, so PRINT is for the output channel, not for seeing results.

A string is shown on the stack wrapped in single quotes ('TEST') so you can tell it apart from a numeric vector. Those quotes belong to the Stack display, not to the value: PRINT writes the raw text, so 'TEST' prints as TEST. Quote characters that are part of the text are kept (a string whose content is T'ES'T prints as T'ES'T). Numbers and booleans print exactly as they appear on the stack.

Identity Model

Ajisai lets you write ordinary comparison words such as EQ, LT, and GTE while the language keeps several “same?” questions separate behind the scenes.

LayerUser meaningWhy it matters
Value equivalenceAre these the same mathematical value?This is what comparison words use.
Structural identityAre they stored the same way internally?Not user-observable; implementations may optimize representation.
Display equivalenceDo two rendered strings look the same?Display helps humans, but it is not the proof of equality.
Conformance equivalenceDo implementations produce the same observable results?This is how ports show they are the same Ajisai language.

Comparison words work at the top layer only: over every Ajisai value they are exact and total, and they answer the mathematical question. The layers below stay out of the value model, so representation and display never affect what a comparison says.
