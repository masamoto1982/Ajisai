Introduction

Ajisai is an AI-first, vector-oriented dataflow language. A program is a sequence of words: values are pushed onto a single stack, and each word consumes operands from the stack and pushes its results. Every number is exact — exact rationals and the algebraic SQRT closure over them, carried in a multiquadratic normal form — so arithmetic and comparison both work without rounding. A number's continued-fraction form is a canonical display derived from the value, not its internal storage.

This reference introduces each feature with short, verified examples. Every example has an "Open in Playground" button; pressing it loads the code into the app's editor so you can run it and see how it behaves.

The Reference is for using Ajisai. If you are implementing or porting the language, the single design authority is the Specification; this page is derived from it for learners and day-to-day users.

How to read the examples

The Expected value column shows the final stack exactly as the language renders it, value by value. Two display conventions matter from the start:

Numbers display as exact fractions in numerator/denominator form — the integer three renders as 3/1. Truth values display as TRUE and FALSE; the absence of a value displays as NIL.

That is the Stack area's standard rendering, and it is what this reference's Expected value column shows. The Stack area also carries a LaTeX checkbox — off by default — that redraws the same values as typeset mathematics: a fraction becomes a stacked fraction, a numeric vector becomes a matrix, and a denominator of one reads as a plain integer, so 3/1 is drawn as 3. That is a second reading of one value, not a second value: the number is the same exact rational either way, nothing is rounded or reduced, and unchecking the box brings the canonical form back. A value with no faithful mathematical reading — a string, NIL, a ragged vector — stays in the standard rendering even with the box checked.

A collection can hold far more elements than are worth drawing, so the Stack area draws a leading part of a large one and ends it with a marker such as … 199900 more. The marker is a statement about the drawing, never about the value: the collection on the stack is complete, every word still sees all of it, and LENGTH reports the real length.

In the text of this reference, anything with a gray background is an Ajisai token. Every symbol token defined by Ajisai is a word in disguise — + is ADD and ^ is VENT — so the gray background is the signal that a mark belongs to the program, not to the prose.

Tokens and Spelling

A program is a sequence of tokens separated by whitespace. A token ends at exactly three things: whitespace, a structural delimiter ([ ] { } ( )), or the start of a comment (# to the end of the line). Nothing else ends a token, so every other character — punctuation included — is an ordinary name character.

The practical consequence is that an operator needs a space around it the same way a word does. 2 + is two tokens; 2+ is a single name that no word answers to, and it fails as an unknown word rather than silently parsing as addition. Brackets and braces are the exception, because they delimit themselves: [ 1 2 ]LENGTH is read exactly like the spaced form, and so is a bracket written flush against another bracket.

A symbol obeys the rule a word obeys because a symbol is a name — one spelled with punctuation. Most are a single character, and the comparison family adds three of two: <=, >= and !=, for LTE, GTE and NEQ. That costs the rule above nothing, because a token ends only at whitespace or a delimiter and never in the middle. What a token means is decided by the whole token, not by its first character: 1/2 is a number because the entire lexeme parses as one, and a bare / is a name for the same reason.

Comments

A # begins a comment that runs to the end of the line, and the line's remaining characters are dropped before anything is tokenized. A # inside a string is ordinary text, so 'a # b' is one three-word string.

WrittenRead asWhy
3 4 +three tokensWhitespace ends each token; + is the symbol for ADD.

Where a line break matters

Whitespace is whitespace: a newline separates tokens exactly as a space does, and a program may be laid out over as many lines as you like. There is one exception, and it is worth knowing before you meet it. Inside a word body, a line break at the body's own level ends one statement and starts the next. A break written inside a { } block or a [ ] vector is interior to that value and separates nothing, so a block may span as many lines as it likes and still be one statement. Nothing else in the language reads line breaks — a COND written on one line and the same COND written down the page are the same program.

Number literals

A decimal literal carries at least one digit on both sides of the point: 0.5 and 5.0 are numbers, while .5 and 5. are not. The point is therefore never the first or last character of a number, which is what lets a lone . be an ordinary name rather than a truncated literal.

A string closes on the quote that sits at a token boundary, which is how a string carries an apostrophe with no escape character: 'It's fine' is one string. A quote followed immediately by a name character stays inside the text, so 'abc'CHARS is an unclosed string rather than two tokens.

A vector literal is a literal all the way through: a bare name written inside [ ] is its own text, never a call and never an error, so [ FOO BAR ] is [ 'FOO' 'BAR' ]. That is how a vector of strings is written without quoting each one, and it is also the one thing that surprises readers once they start naming values — see A name inside [ ] is text.

[ ] is the empty vector — a collection of no values, and an ordinary value you can write, nest, and measure ([ ] LENGTH is 0). It is not NIL: NIL is the absence of a value, which is a different thing from a collection that happens to hold none. Operations that come up empty answer [ ] rather than bubbling — [ 1 2 3 ] { 5 GT } FILTER is [ ].

Exact Numbers

Every numeric value is exact; its continued-fraction form is a canonical display derived from the value, not its internal storage. Integer, fraction, decimal, and scientific-notation literals are all surface forms of the same exact value — 0.5 is one half, not a binary approximation. Stack and Modifiers

Words take their operands from the stack and push their results back. Consumption is the default: a word eats the operands it reads. The single modifier, written before a word, is the one explicit way to change that:

ModifierEffect
KEEPRetain the operands of the next word and push its result as well.

KEEP prefixes the next word only, and it carries no symbol — it is written out. That is the whole modifier system: one explicit operation for the non-default behavior, and no Forth-style stack shufflers to go with it. Everything else about how a word behaves is in the word itself, so reading a call means reading a name and at most one prefix.

The word it prefixes may be one of your own, and it means the same thing there: KEEP retains the operands of the call, never anything the body happens to use inside itself. Given { 2 MUL } 'DOUBLE' DEF, 5 KEEP DOUBLE is 5/1 10/1 — the body's own 2 is the body's business and never reaches your stack.

One consequence is worth keeping in your pocket. A word that gives back exactly what it was handed — { 1 COLLECT [ 0 ] GET } 'ID' DEF, which wraps a value and unwraps it again — turns KEEP into a copier for any value: 'hi' KEEP ID leaves two strings, and the same works for truth values and code blocks, which no arithmetic trick reaches.

A word that answers with nothing is no exception. BIND, DEF, DEL and LOOKUP push no result, so under KEEP what you are left with is their operands, unchanged: 5 KEEP 'X' BIND names the value and leaves 5/1 'X' where they were.

The higher-order words are the one exception, and it is worth knowing before you meet it. MAP, FILTER, FOLD, ANY and ALL retain the collection they walk and nothing else, so [ 1 2 ] KEEP { 2 MUL } MAP is [ 1/1 2/1 ] [ 2/1 4/1 ] — no block, and for FOLD no starting accumulator either. The block says what the call is rather than being data the call read, and the accumulator has been folded into the answer. Every other word keeps everything it read, [ 10 3 ] KEEP [ 0 ] GET included, which leaves all three of [ 10/1 3/1 ] [ 0/1 ] 10/1.

Arithmetic

The arithmetic words act element-wise between vectors, and a one-element vector broadcasts across a longer one. Each word has a canonical English name; the symbol is sugar:

Broadcasting is a rule about axes, not only about one-element vectors. Two vectors are paired axis by axis starting from the innermost, an axis the shorter one does not reach counts as length 1, and an axis of length 1 is reused across the other side's length — so [ 1 2 3 ] [ 10 ] * is [ 10/1 20/1 30/1 ] and [ [ 1 2 ] [ 3 4 ] ] [ 10 20 ] * is [ [ 10/1 40/1 ] [ 30/1 80/1 ] ]. Anything else is an error: [ 1 2 3 ] [ 10 20 ] * cannot pair 3 with 2. A scalar needs no axes and combines with every element however the vector is nested, ragged ones included; two vectors can only broadcast when both are rectangular.

The remaining numeric words live here too: ABS and NEG for sign, MIN and MAX over two numbers, SQRT, the rounding pair FLOOR and ROUND, and QUANTIZE, which rounds to the nearest multiple of 1/d and is the one to reach for in a loop — see Iterative Numerics. Every one of them lifts. MIN, MAX and SQRT broadcast on the same rule as +, so a rectifier is [ -1 2 -3 ] 0 MAX — [ 0/1 2/1 0/1 ] — a per-feature standard deviation is one SQRT over the vector of variances, and the element-wise smaller of two vectors is [ 1 5 3 ] [ 4 2 6 ] MIN. No MAP and no block: reach for one only when the operation itself is not a numeric word. A lane that misses SQRT's domain bubbles alone, so [ 4 -1 ] SQRT is [ 2/1 NIL ] rather than a failed vector.

NIL and the Bubble Rule

The failure model in one line: could not produce a value → a bubble; used incorrectly → an error. A well-formed operation that cannot produce a result projects onto NIL — a "bubble" carrying a structured reason — while malformed use (wrong types, missing operands) raises an ordinary error.

Bubbles flow: arithmetic and comparison are NIL-passthrough, so a NIL operand makes the result NIL without crashing the pipeline. Two words look at a bubble without disturbing it — NIL? asks whether the top value is one, and NIL-REASON reads the reason it carries. Both leave the value in place and push the answer above it. At the end, VENT (^) supplies a fallback.

GET takes as many indices as you give it. One index answers with the element itself; several answer with a vector of the selections, in the order the indices name them — so picking out a few positions, reordering, or reversing is one call, and an index that names nothing leaves a NIL at that position rather than spoiling the rest.

Read that rule twice when the index list is computed rather than written, because it means the shape of the answer follows the data: a gather by two indices gives a vector, and a gather by one gives the bare element. A selection that happens to narrow to a single position — the left side of a split, a class with one member — therefore answers with a scalar, and the LENGTH or FOLD written for the vector case fails on it. When you want a vector whatever the count, gather one index at a time and let MAP collect the results, which is a vector of the same length as the index list however long that is:

Higher-Order Words

A code block { } is a first-class value. The higher-order words apply a block — or the quoted name of a defined word — across the elements of a vector.

Whatever the block leaves is the mapped element, exactly as it stands. What a block sees

A block has no stack discipline of its own. The word that evaluates it decides what the block can reach and what it may leave behind, and reading the wrong rule is the difference between a + inside the block finding two operands and finding none. There are five rules, and the block's own text does not say which applies to it — the word receiving it does.

Evaluated byThe block seesThe block leaves
A word body (DEF)the whole stackwhatever it pushes, however many
EXECthe whole stackwhatever it pushes, however many
COND guard, and the body that firesone value: the dispatch value, aloneexactly one — the top; leaving none is an error, and anything under the top is discarded
MAP FILTER ANY ALLone value: the current element, aloneexactly one — the mapped element, or a truth value for the predicate words; leaving none is an error, and anything under the top is discarded
FOLDtwo values: the accumulator, then the elementexactly one: the next accumulator; leaving none is an error, and anything under the top is discarded

So { + } 'ADDW' DEF followed by 3 4 ADDW gives 7, and so does 3 4 { + } EXEC — both see the whole stack. But 100 [ 1 2 ] { + } MAP is a stack underflow: the block sees one element and the 100 is not in its frame.

"Anything under the top is discarded" is worth reading twice, because it is silent. A predicate that leaves two values passes: [ 1 2 3 ] { 1 GT TRUE } FILTER keeps everything, because the TRUE on top is the answer and the comparison beneath it is thrown away. Only leaving nothing is an error. If a higher-order block gives an answer you cannot explain, count what it leaves.

When something inside a block fails, the diagnosis names the word that failed, not the word that ran the block: [ 1 2 ] { 'x' 1 ADD } MAP reports ADD, with inside MAP beside it and the position of the statement that ran. A word you defined is where that stops — a call to it reports the word, because from the caller's side that is what failed.

A block written inside another block is data where it is written. It is evaluated only when the word that receives it runs it, under that word's row above rather than the enclosing block's — which is why a word may call itself from inside a { } it hands to MAP or EXEC, and why that call is an ordinary recursive call.

Writing a word that takes two arguments

Ajisai has no DUP, SWAP, DROP or ROT, and that is deliberate rather than missing: several values travel in a vector, not on the stack. A word that needs two arguments takes one vector of two, and the caller either writes it — [ 3 4 ] — or builds it from computed values with COLLECT.

When you do need a position rather than a reduction, read it with GET: [ 0 ] GET is the first element and [ -1 ] GET the last, so { SORT [ -1 ] GET } 'PMAX' DEF answers the larger of a pair. REVERSE is the vector's swap, and TAKE with CONCAT rebuilds a vector from slices of one.

The one duplication device is KEEP. Prefixed to a word that reads one value and pushes one, it leaves the operand underneath the result, so KEEP REVERSE REVERSE copies the vector on top and KEEP ID — with the identity word of Stack and Modifiers — copies a value of any kind at all. Prefixed to a two-operand word it keeps both operands, which is rarely what you want: [ 10 3 ] KEEP [ 0 ] GET leaves the index vector on the stack as well.

Code as data

A code block sitting on the stack shows the source it was written as, braces and all — { 2 MUL }, and { } for the empty one. It is a value of its own kind, so NIL? on it is FALSE and EXEC runs it; if you are copying blocks around with KEEP ID, that is what you will see in the Stack panel.

A code block and a vector are different kinds of value: a vector is data and is never executable, and EXEC accepts only a code block. REFLECT is the one crossing between them. It turns a code block into a canonical vector of token records — and turns that vector back into the block — without evaluating anything and without consulting the dictionary.

Putting a runtime value inside a block

A block is source, so a value you computed while the program was running is not in it. MAP and FILTER take a block and nothing else, which raises a real question: how do you filter by a threshold you only learn at run time? { 5 LT } tests against a literal five, and there is no five to write when the number came out of the program.

REFLECT answers it in both directions. Build the token records for the block you want — with the runtime value converted to its lexeme by STR — and cross back into a block with REFLECT. The result is an ordinary block, and every word that takes one accepts it.

This is the one place where a number without a lexeme shows up as a limit. The numeric grammar writes integers and ratios, so an exact irrational such as 2 SQRT has no spelling for STR to produce and STR answers NIL with reason invalidEncoding rather than a rational that is nearly it. To embed one, choose a resolution and say so: 2 SQRT 10000 QUANTIZE STR is '7071/5000', and the approximation is in your source where you can see it.

This is the whole of partial application in Ajisai — there is no separate word for it, and none is needed, because a block is a value whose contents you can compute.

Conditionals

COND evaluates guard-and-body clauses in order and executes the body of the first guard that is true. In the clause form, | separates the guard from the body and each clause occupies exactly one line; TRUE makes an always-true else guard.

The else clause can also be spelled IDLE, and that is the spelling to prefer. IDLE is not one of the 59 Words and you will not find it in the Dictionary panel: it is a keyword read positionally, meaningful only as a guard, and it means this clause fires when no earlier one did. TRUE reaches the same outcome by pushing a value the guard then reads, which works but says less; IDLE says which clause is the fallback.

IDLE fires where it is written. Clauses are tried top to bottom and IDLE takes its turn in that order, so anything written below an IDLE is unreachable. Put it last — which is what "fallback" means anyway.

Sample codeExpected valueNotes
[ 0 ] { [ 0 ] < | 'negative' } { [ 0 ] = | 'zero' } { TRUE | 'positive' } COND 'zero' Clause form: guard left of |, body right; one clause per line by convention.
Open in Playground
Sample codeExpected valueNotes

Each guard answers TRUE or FALSE, so a clause either fires or does not. If no clause matches and no else clause is present, COND raises an error.

One clause per line is the canonical form, and the Format button produces it, but it is a layout preference rather than a rule: a COND collapsed onto one line runs and means the same thing. Write it down the page anyway — a COND is read by scanning its guards, and that only works when they are stacked.

What a clause sees

A COND clause does not run on the stack you can see. Every guard, and the body of the clause that fires, runs in an isolated frame holding exactly one value — the value COND is dispatching on — and exactly one value comes back out of it: whatever is on top when the body finishes. This is different from a word body or EXEC, which see the whole stack; see What a block sees for all five rules side by side.

Two consequences are worth writing down before you meet them. A clause body cannot reach values that were on the stack before the COND: 1 2 3 4 followed by a clause whose body is + is a stack underflow, because + finds only the dispatch value. And a body that ends with several values keeps only the top one — { TRUE | 7 8 9 } answers 9, and the 7 and 8 go with the frame.

The isolation is what makes recursion over COND practical. A clause body that builds working values on its way to a self-call does not have to clean them up: they cannot survive the frame, so each turn of the recursion starts from one value no matter how much scaffolding the previous turn built.

Strings

A string is quoted with ' and shows in quotes on the stack. Those quotes are a display affordance, not part of the value: PRINT writes the raw text ('TEST' prints as TEST — see Output), while a string nested in a collection keeps its quotes ([ 'AB' 'CD' ] stays [ 'AB' 'CD' ]). Strings convert to and from numbers and characters with the cast words.

A string is one of the six value domains, not a vector of code points: 'A' [ 65 ] EQ is FALSE, and arithmetic on a string is an error rather than arithmetic on its codes. The empty string '' is an ordinary string, not NIL.

Because a string is not a vector, the collection words do not take one. LENGTH, GET, REVERSE and CONCAT all raise an error on a string; cross into the vector domain with CHARS first ('abc' CHARS LENGTH is 3). Concatenation is JOIN, which is the word for turning a vector of strings into one string: [ 'ab' 'cd' ] JOIN is 'abcd'. To join values you computed rather than wrote, gather them with COLLECT first — 'a' 'b' 2 COLLECT JOIN.

Defining Words

A new word is defined from a code block and a name: { body } 'NAME' DEF. The body runs each time the word is called.

What DEF checks, and what it does not

DEF stores the body; it does not resolve the names inside it. A definition whose body calls a word that does not exist is accepted and reported as defined, and the failure surfaces the first time the word is called: { TOTALL 1 } 'FOO' DEF succeeds, and only running FOO reports Unknown word: TOTALL.

This is a design choice rather than a missing check. Names resolve at call time, which is exactly what lets one word call another that is defined after it — so a pair of words may call each other, and a definition never has to be ordered around its dependencies.

The cost is that a mistyped name in a body sits quietly until something calls it. The headless CLI is where that is caught ahead of time: ajisai check resolves every name in a file without executing anything and reports the unknown ones, and ajisai check --contract additionally verifies declared word contracts. The Playground has no equivalent — in the app, calling the word is the check.

Managing words

DEL deletes a user word by quoted name. Dependencies are tracked: a word that other words depend on cannot be deleted at all, so a dangling reference is impossible — delete the dependents first.

Word names are case-insensitive (add10 and ADD10 are the same word) and conventionally follow an action-object style such as APPLY-GAIN. How a name is matched to a definition is the subject of Dictionaries and Word Identity.

Naming a Value

A stack hands you one value at a time, and most expressions worth writing use a value more than once. A residual feeds both the squared error and the gradient; a threshold feeds both the comparison and the report; a pair of coordinates feeds a sum and a difference. KEEP copies, which sounds like enough and is not — derive something from the upper copy and the result lands on the lower one, so the second use is buried under the first.

BIND gives the value a name instead. It takes the value and the name, consumes both, and from then on the name is the value, as often and in whatever order you like.

Sample codeExpected valueNotes
[ 4 9 ] [ 'A' 'B' ] BIND A B ADD A B SUB 2 COLLECT [ 13/1 -5/1 ] Two names from one vector, each read twice. Written on the stack alone this needs a matrix and a fold.
Open in Playground

One name takes the whole value; several destructure a vector of the same length, position by position. The lengths must match exactly — a longer vector would silently drop its tail and a shorter one would name nothing.

Sample codeExpected valueNotes
5 'T' BIND T T MUL 25/1 A single name. [ 'T' ] means the same thing, as with GET's index.
Open in Playground

A name inside [ ] is text, not the value

This is the one place a binding will surprise you, and it is worth meeting here rather than in your own program. Inside a vector literal a bare name is its own text — that is the rule for [ ] generally, and a bound name is no exception. So after 3 'K' BIND, [ K ] is the one-element vector [ 'K' ], not [ 3/1 ].

It catches people because the idioms of this Reference are written [ 0 ] GET and [ 3 ] TAKE, so the natural next line is XS [ K ] TAKE — and that fails with expected integer, got string. Two ways to say what you meant:

Sample codeExpected valueNotes
3 'K' BIND [ 1 2 3 4 5 ] K TAKE [ 1/1 2/1 3/1 ] Write the name bare. A count or an index may be a plain number, so nothing needs wrapping.
3 'K' BIND K 1 COLLECT [ 3/1 ] When you do want the one-element vector, build it: COLLECT reads the value, where [ ] reads the text.
Open in Playground

How far a name reaches

A binding belongs to the frame that made it — the word body, or the run itself if you typed it straight in — and it lives exactly as long. Two rules follow, and between them they are the whole story:

A name reaches the blocks written in its frame. A block that MAP, FILTER, FOLD, EXEC or a COND clause runs is not a new frame for names, so it reads the ones around it. The isolation those words enforce (see What a block sees) is of the stack, and a name is not on the stack. This is what lets a predicate test against a value the program only learned at run time:

Sample codeExpected valueNotes
3 'LIMIT' BIND [ 1 5 2 9 ] { LIMIT LT } FILTER [ 1/1 2/1 ] The block is written where LIMIT is bound, so it can say LIMIT.
Open in Playground

A name does not reach into a word you call. A word's meaning is its operands and the dictionary and nothing else, which is what makes a word readable on its own — so a body reads its own bindings and never its caller's. If you need the value in there, pass it as an operand, which is what operands are. Getting this wrong says so plainly rather than reporting an unknown word.

A word that binds leaves no names behind for its caller, and a run's bindings are gone when the run ends. That is deliberate: a name that outlived its frame would be a second, editable name space sitting next to the dictionary, and there is one name space here. For data you want to keep, define a word — { [ 1 2 3 ] } 'XS' DEF — which is the dictionary doing the job it is for.

A name is a word or a binding, never both

You cannot bind a name that a Core or User word already has, and you cannot define a word whose name is currently bound. Both directions are refused, so you never have to work out which one a name resolved through. Short scratch names — W, DX, LIMIT — are exactly right here, and unlike a word name they attract no naming-convention warning: they are local, and their scope is on the screen in front of you.

Words Ajisai Does Not Have

The vocabulary is 59 words and is meant to stay that way: a word that a user definition already expresses does not belong in Core. So the sums, transposes and argmins that other languages spell as words are spelled here as short phrases, and the ones that come up most are written out below. Each is verified, and each is a fine body for a DEF of your own if you use it twice.

[ 1 2 3 ] [ 4 5 6 ] MUL 0 { ADD } FOLD 32/1 Dot product: multiply element-wise, then sum.
[ [ 1 2 ] [ 3 4 ] ] 'A' BIND [ 5 6 ] 'V' BIND
A { V MUL 0 { ADD } FOLD } MAP		 [ 17/1 39/1 ] Matrix times vector: one dot product per row.

Ordering by a key, ties and all

Sorting the values and looking their positions back up is the obvious way to get an ordering, and it is wrong exactly where it matters: with two equal distances, SORT then INDEX-OF finds the same position twice, so "the 3 nearest" can hand you two neighbours or four. Rank each position instead, counting how many positions come before it — earlier value, or equal value and lower index. That is a total order, so the ranks are a permutation and the ordering is exact and stable.

Sample codeExpected valueNotes
[ 18 13 1 1 13 2 ] 'DS' BIND
[ 0 5 ] RANGE 'IX' BIND
IX { 'I' BIND I 1 COLLECT 'IV' BIND
     DS IV GET 'DI' BIND
     IX { 'J' BIND J 1 COLLECT 'JV' BIND
           DS JV GET 'DJ' BIND
           DJ DI LT
           DJ DI EQ J I LT AND
           OR } FILTER LENGTH } MAP 'RANKS' BIND
IX { 'P' BIND RANKS P INDEX-OF } MAP 3 TAKE		 [ 2/1 3/1 5/1 ] The 3 nearest of six distances, two of which tie at 1. Drop the 3 TAKE for the whole ordering, [ 2/1 3/1 5/1 1/1 4/1 0/1 ]. RANKS is a permutation, so the last line reads it backwards to turn rank-by-position into position-by-rank.

Iterative Numerics

Exact arithmetic changes what a loop costs. Every other section of this Reference is about what a program means; this one is about what repeating it costs, because that is the one place where exactness asks something of you in return.

Where the cost comes from

An exact rational is stored as a numerator over a denominator, and a fraction times a fraction has the product of the denominators. Multiply once and nothing happens. Multiply in a loop — which is what gradient descent, Newton's method, k-means, the power method and every other iterative scheme do — and the denominator grows step over step. Nothing is lost and nothing is approximated; the number is exactly right. It is just that the digits are recording how the value was computed, and the history is longer every round.

Here is a relaxation step, x moving a tenth of the way toward 2 each time. DELTA is the correction and STEP applies it; the loop is a FOLD over a range whose elements are only a counter, so the block discards the element and keeps the accumulator.

Sample codeExpected valueNotes
{ 2 SUB 1/10 MUL } 'DELTA' DEF
{ KEEP DELTA NEG ADD } 'STEP' DEF
[ 0 6 ] RANGE 10 { 2 COLLECT [ 0 ] GET STEP } FOLD		 7282969/1250000 Six steps from 10. Already a 7-digit denominator; the value is about 5.83.
Open in Playground

The shape of the growth is the problem, not the size of any one number. Twenty steps of the same loop answer 359418989131512359209/125000000000000000000 — 21 digits over 21 digits, for a value near 2.875. Each further step multiplies the denominator by ten again, so the cost per step rises without bound while the answer barely moves. This is worth knowing before you meet it: a loop that runs instantly for thirty iterations can crawl at three hundred.

QUANTIZE: naming the resolution

QUANTIZE rounds a value to the nearest multiple of 1/d, so its denominator divides d and can never grow past it. Applied once per step, it throws away the derivation and keeps the value:

Sample codeExpected valueNotes
{ 2 SUB 1/10 MUL } 'DELTA' DEF
{ KEEP DELTA NEG ADD 1000 QUANTIZE } 'STEP' DEF
[ 0 20 ] RANGE 10 { 2 COLLECT [ 0 ] GET STEP } FOLD		 2877/1000 Twenty steps, and the denominator is still 1000. The unquantized run answers 2.875351… — the same number to the resolution that was asked for.
Open in Playground

This is an approximation, and that is the point: it is one you wrote down. The resolution is a literal in the source, at a place you chose, and every value downstream of it is exactly a multiple of 1/d. Nothing is rounded behind your back, and nothing decides for you how much precision an answer deserves.

QUANTIZE lifts over vectors like the other arithmetic words, so a whole parameter vector is quantized in one call, and at d equal to 1 it is exactly ROUND.

Sample codeExpected valueNotes
[ 119/125 32/125 ] 10 QUANTIZE [ 1/1 3/10 ] One call per step, whatever the shape of the state.
Open in Playground

A closed form beats a loop

Before reaching for an iterative method, check whether the problem has a closed form — because in exact arithmetic that is not merely faster, it is a different kind of answer. Least squares, ridge regression with a rational penalty, k-nearest neighbours, naive Bayes over rational probabilities, a Gini-split decision tree, the perceptron and the simplex method all have exact solutions with no iteration in them, and Ajisai returns the coefficients as the rationals they are rather than as the nearest representable float. An R² that comes back as 529/532 is not an artefact of the language; it is the answer.

Transcendental functions — an exponential, a logarithm, an arbitrary power — are not in the vocabulary, because no rational answer to them exists and Ajisai does not return numbers it cannot justify. Methods built on them (logistic regression, softmax, cross-entropy, a Gaussian likelihood) are outside what this language computes, and SQRT is the one irrational it does construct, exactly, as an algebraic number.

Dictionaries and Word Identity

The dictionary has two tiers, and those two are the whole of it. Core holds the 59 canonical words and is sealed: a Core name cannot be redefined or deleted. User holds everything you define with DEF.

Those 59 words divide into a 36-word Semantic Kernel and 23 Standard words. The Kernel words are the ones that build or observe a kind of value, or that are the single explicit way to do something — run a code block, recover from a NIL, change the dictionary, print, cross between code and data. The Standard words give a frequent idea one fixed name and contract: SUB, MIN, SORT, MAP, TRIM and the rest. The division tells you where a word sits in the design; it changes nothing about how you use one. All 59 are ordinary Core words in the same flat dictionary, reached by their plain names, with the same contracts, examples, and error conditions. Each word's tier is listed in the Word Reference and reported by LOOKUP.

A name resolves in Core or in User, and User never shadows Core. A word's name is therefore its whole address — there is no qualified form, no dictionary to select, and no way for a bare name to be ambiguous. Names are case-insensitive, so add10 and ADD10 are the same word.

Sample codeExpected valueNotes
{ 10 ADD } 'ADD10' DEF 5 ADD10 15/1 A defined word is reached by its name.
{ 1 } 'ADD' DEF error Core is sealed, so a Core name cannot be taken.
{ 10 ADD } 'ADD10' DEF { 20 ADD } 'ADD10' DEF 5 ADD10 25/1 A redefinition rebinds the one User entry — unless another word depends on it, which DEF refuses.

Word identity

Every word has a content identity: a digest over its normalized definition and the identities of the words it calls. Two definitions with the same identity are the same word, whatever they are named, and changing a definition changes the identity of everything that depends on it. That is what makes DEF and DEL refuse to disturb a word something else still references — the dependency is on the word, not on the spelling.

Output

PRINT writes the top stack value to the output area. Like any word it consumes its operand by default; with KEEP the value also stays on the stack. The Playground always shows the final stack, so PRINT is for the output channel, not for seeing results.

A string is shown on the stack wrapped in single quotes ('TEST') so you can tell it apart from a numeric vector. Those quotes belong to the Stack display, not to the value: PRINT writes the raw text, so 'TEST' prints as TEST. Quote characters that are part of the text are kept (a string whose content is T'ES'T prints as T'ES'T). Numbers and booleans print exactly as they appear on the stack.

42 KEEP PRINT 42/1 The value goes to the output area and, thanks to KEEP, stays on the stack.

Identity Model

Ajisai lets you write ordinary comparison words such as EQ, LT, and GTE while the language keeps several “same?” questions separate behind the scenes.

LayerUser meaningWhy it matters
Value equivalenceAre these the same mathematical value?This is what comparison words use.
Structural identityAre they stored the same way internally?Not user-observable; implementations may optimize representation.
Display equivalenceDo two rendered strings look the same?Display helps humans, but it is not the proof of equality.
Conformance equivalenceDo implementations produce the same observable results?This is how ports show they are the same Ajisai language.

Comparison words work at the top layer only: over every Ajisai value they are exact and total, and they answer the mathematical question. The layers below stay out of the value model, so representation and display never affect what a comparison says.
