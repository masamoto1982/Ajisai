はじめに

Ajisaiは、AIファーストでベクトル指向のデータフロー言語です。プログラムはワードの並びとして構成されます。値は単一のスタック上で管理され、各ワードがスタックからオペランドを取り出し(消費し)、処理結果をスタックに積みます。

水のメタファー

Ajisaiという名前は紫陽花(あじさい)に由来し、「水を湛える器」と解釈されることがあります。Ajisaiはこの水の比喩を設計の軸に据えています。Stack(実体はVector)は水を湛える器であり、そこに注がれる水は値——もっとも純粋な形はSQRTで拡張された厳密な分数——です。プログラムを実行することは器に水を注ぐ行為であり、注いだ水が入力から出力へと動いていく過程が流れ、出力(PRINT)としてその水面に現れる痕跡が波紋です。

器の中には、水以外にもう一つだけ混じるものがあります。整った操作が値を作れなかったときに残る泡——NILです。泡は不在であって虚偽ではなく、理由を持ったまま下流へ流れていきます。これに対し、操作や入力の形そのものが誤っているときは、水路が持ちこたえられずに決壊し、評価はその場で止まります。決壊は流れの中を運ばれる値ではなく、プログラムを終わらせる唯一の結果です。

数値の厳密性

すべての数値は厳密に扱われます。厳密な有理数と、それらに対する代数的な平方根(SQRT)の閉包(多重二次正規形)で保持され、算術演算や比較演算は丸め誤差なしで実行されます。なお、連分数形式は値そのものから導出される正準表示であり、内部の格納形式ではありません。

例の読み方

各セクションのExpected value(期待値)列には、プログラム実行後の最終的なスタックの状態を、言語の描画仕様に準拠して表示しています。あらかじめ把握しておくべき表示規則は次のとおりです。

1. 基本的な表示規則

  • 数値: 分子/分母の形の厳密な分数として表示されます(例: 整数3は3/1と描画)。
  • 真偽値: TRUEまたはFALSEと表示されます。
  • 値の不在: NILと表示されます。

これらはStack領域における標準的な描画形式であり、本書のExpected value列の記載内容と一致します。

2. LaTeX表示モード(数式組版)

Stack領域のLaTeXチェックボックス(初期状態はオフ)を有効にすると、同じ値を組版された数式として再描画できます。

  • 分数は積み重ね分数(縦並びの分数)として表示されます。
  • 数値ベクトルは行列形式で描画されます。
  • 分母が1の分数は整数として扱われ、3/1は3と描画されます。

これは同一の値に対するもう一つの表示形式であり、内部的な値が変化するわけではありません。どちらの表示モードでも厳密な有理数のままであり、丸めや勝手な約分は行われません。チェックを外せば元の正準形に戻ります。文字列やNIL、形状の不揃いなベクトルなど、数学的に一意な組版表現を持たない値は、チェックを有効にしても標準表示のまま維持されます。

3. 大きなコレクションの省略表示

コレクションの要素数が非常に多い場合、Stack領域には先頭部分のみが描画され、末尾に…あと199900件のようなマーカーが付与されます。このマーカーは画面描画上の都合による注記であり、内部データが切り詰められているわけではありません。スタック上のコレクション自体は完全な状態で保持されており、すべてのワードはデータ全体を参照します(LENGTHワードも実際の要素数を返します)。

4. 記号・トークンの表記

本書の本文中で灰色の背景が付いているテキストは、すべてAjisaiのトークン(コード要素)を表します。Ajisaiにおける記号トークンは、すべて特定のワードの別表記です(例: +はADD、^はVENT)。灰色の背景は、その表記が地の文ではなくプログラムコードの一部であることを示しています。

トークンと綴り

Ajisaiのプログラムは、空白などで区切られた一連のトークンの並びです。

トークンの区切り規則

トークンが終わる(区切られる)条件は、次の3通りだけです。

  • 空白文字(スペース、タブ、改行)
  • 構造区切り文字([ ] { } ( ))
  • コメントの開始(行末までの#)

これ以外の文字は、記号や句読点を含めすべて通常の名前(識別子)を構成する文字として扱われます。

(と)はトークンを区切る構造文字の一種ですが、ソースコードの中では使えません——書けば必ずエラーになる予約済みの記号です。無理数の値を入れ子の連分数として表示するための専用表記であり、コードブロックには常に{ }を使います。詳しくは厳密な数を参照してください。

演算子と空白の必要性

一般的な演算記号もワード(名前)の一種であるため、前後に空白が必要です。2 +は2と+の2つのトークンとして正しく解釈されます。2+は「2+」という1つの名前とみなされ、加算ではなく未定義ワードとしてエラーになります。

角括弧[ ]や波括弧{ }は例外で、それ自体が前後の境界となるため、前後に空白がなくても独立したトークンとして区切られます(例: [ 1 2 ]LENGTHは空白で区切った場合とまったく同じに解釈されます)。

記号ワードとトークン判定

Ajisaiにおける記号は、単に記号で綴られた名前にすぎません。ほとんどの記号は1文字ですが、比較系のワードには2文字の記号が3つあります(<=はLTE、>=はGTE、!=はNEQに対応)。トークンが終わるのは空白または区切り文字のときだけで、途中で終わることは決してないため、これは上の規則に何のコストも課しません。トークンの意味は先頭の文字ではなく、トークン全体の字句によって決まります。たとえば1/2は全体が分数リテラルとしてパースされ、単独の/は除算ワードの名前としてパースされます。

コメント

#は行末まで続くコメントを開始します。#からその行の末尾までの文字は、トークン化される前に破棄されます。なお、文字列リテラルの中にある#は通常のテキストとして扱われます(例: 'a # b'は1つの文字列です)。

改行が意味を持つところ

基本規則として、改行はスペースと同様にトークンを区切る空白として扱われます。そのため、プログラムは好きなだけ多くの行にわたって書いてかまいません。唯一の例外があり、出会う前に知っておく価値があります——ワード定義の本体では、その本体自身の階層にある改行が1つの文の終わりと次の文の始まりを意味します。{ }ブロックや[ ]ベクトルの内部に書かれた改行はその値の内側にあり、何も区切りません。したがってブロックは何行にわたっても1つの文のままです。それ以外の場所(COND式など)では改行に特別な意味はなく、1行で書いても複数行に分けて書いてもまったく同じプログラムとして実行されます。

数値リテラル

小数リテラルは、小数点の両側に少なくとも1桁の数字を必要とします——0.5や5.0は数ですが、.5や5.は数ではありません。この規則により小数点が数の先頭や末尾の文字になることは決してなく、単独の.を不完全なリテラルではなく通常の名前として安全に使えます。

文字列リテラル

文字列リテラルは、トークン境界に位置する引用符(')で閉じます。文字列の内部にアポストロフィがあっても、直後に空白や区切り文字が続かなければ文字列は終了しません。これにより、エスケープ文字なしで'It's fine'のような文字列を1つのリテラルとして書けます。引用符の直後に名前用文字が続く場合はテキストの内側にとどまるため、'abc'CHARSは2つのトークンではなく閉じられていない文字列として扱われます。

リテラル中の裸の名前

ベクトルリテラルは最後まで徹底してリテラルです。[ ]の中に書かれた裸の名前はそれ自身のテキストであり、ワードの呼び出しとして実行されることも未定義エラーになることもありません。したがって[ FOO BAR ]は[ 'FOO' 'BAR' ]と完全に等価です。これは各要素を引用符で囲まなくても文字列のベクトルを書ける方法であり、また値に名前を付け始めた読者を驚かせる唯一のことでもあります。変数やワードを実行した結果をベクトルに入れたい場合は、リテラルではなくCOLLECTのような実行時のコレクション構築ワードを使ってください——[ ]の中の名前はテキストになるを参照。

[ ]とNILの違い

[ ]は空ベクトルです——値を1つも持たないコレクションであり、書いたり入れ子にしたり測ったりできる普通の値です([ ] LENGTHは0)。これはNILではありません。NILは値の不在であり、たまたま何も保持していないコレクションとは別のものです。結果が空になる操作は、泡になるのではなく[ ]を返します——[ 1 2 3 ] { 5 GT } FILTERは[ ]です。

厳密な数

Ajisaiにおけるすべての数値は厳密数として扱われます。

数値の表現と定義域

整数、分数、小数、指数表記など各リテラルは、同一の厳密な値を表す異なる表記形式にすぎません(例: 0.5は2進浮動小数点による近似値ではなく、厳密な1/2そのものです)。

無理数の描画形式と構文規則

無理数を出力する際、値そのものは( 1 ( 2 ( 2 ( 2 ... ) ) ) )のような入れ子の連分数として、表示用の予算で打ち切って描画されます。この入れ子形式は表示専用の出力であり、ソースコードの構文ではありません。プログラム中で( )を直接書くことは、構文エラー(予約記号)として拒否されます。

スタックと修飾子

Ajisaiのワードは、スタックからオペランド(引数)を取り出し、結果をスタックへ積み戻します。取り出した値をその場で消費するのが既定の挙動です——ワードは自分が読み込んだ値をスタックから取り除きます。この既定の挙動を変える、明示的な方法がただ1つだけあります。それがワードの前に置く修飾子です。

唯一の修飾子KEEP

修飾子効果
KEEP次のワードのオペランドを保持したまま、その結果も併せて積む。

KEEPは直後の1つのワードだけに前置され、記号は持たず、そのまま綴って書きます。Ajisaiの修飾子はこれひとつだけです——既定でない挙動のための明示的な操作はこれひとつだけで、値の複製や入れ替え、破棄のためだけに用意された専用のワード群のようなものはありません。ワードがどう振る舞うかについてのそれ以外のすべては、ワードそのものに内在しています。したがって呼び出しを読むということは、名前と、たかだか1つの前置修飾子を読むことにすぎません。

補足: Forthのような古典的なスタック指向言語には、値の複製・入れ替え・破棄を担う専用のワード群(いわゆる「スタックシャッフラー」)が用意されていることがありますが、Ajisaiにはそうした仕組み自体がなく、KEEPひとつがその役割を兼ねます。

呼び出し単位で効く

KEEPを前置する対象は自分で定義したワードでもよく、その場合も意味は変わりません。KEEPが保持するのはその呼び出しのオペランドであり、本体がたまたま内部で使う値ではありません。{ 2 MUL } 'DOUBLE' DEFがあるとき、5 KEEP DOUBLEは5/1 10/1になります——本体自身が持つ2は本体内部の話であり、あなたのスタックには決して届きません。

あらゆる値のコピー装置になる

覚えておく価値のある帰結が1つあります。渡された値をそのまま返すワード——{ 1 COLLECT [ 0 ] GET } 'ID' DEF、これは値を包んでまた取り出すだけです——を用意しておくと、KEEPはあらゆる種類の値のコピー装置になります。'hi' KEEP IDは2つの文字列を残しますし、算術演算では複製できない真偽値やコードブロックについても同じことが成り立ちます。

結果を積まないワードも例外ではない

BIND、DEF、DELのように結果を何も積まないワードも例外ではありません。これらにKEEPを付けたときに残るのは、そのオペランドそのまま、変わらぬ姿です——5 KEEP 'X' BINDは値に名前を付けつつ、5/1 'X'を元の場所に残します。

唯一の例外: 高階ワード

高階ワードだけが例外であり、出会う前に知っておく価値があります。MAP、FILTER、FOLD、ANY、ALLは、自分が走査するコレクションだけを保持し、それ以外は保持しません。したがって[ 1 2 ] KEEP { 2 MUL } MAPは[ 1/1 2/1 ] [ 2/1 4/1 ]です——ブロックは残らず、FOLDの場合は開始時の累積値も残りません。ブロックは呼び出しが読み取ったデータというより、その呼び出しが何であるかを表すものであり、累積値は答えに畳み込まれています。それ以外のすべてのワードは、読み取ったものをすべて保持します。[ 10 3 ] KEEP [ 0 ] GETも例外ではなく、[ 10/1 3/1 ] [ 0/1 ] 10/1の3つすべてが残ります。

ブロードキャスト規則

ブロードキャストは、単に要素数1のベクトルを拡張するだけの規則ではなく、多次元ベクトルの軸全体に適用される一貫した規則です。

  • 軸の対応付け: 2つのベクトルは最も内側の軸から順に対応付けられます。
  • 長さ1の軸の拡張: 短いベクトルの届かない軸は長さ1とみなされ、長さ1の軸は相手側の長さに合わせて繰り返し使われます(例: [ 1 2 3 ] [ 10 ] *は[ 10/1 20/1 30/1 ]、[ [ 1 2 ] [ 3 4 ] ] [ 10 20 ] *は[ [ 10/1 40/1 ] [ 30/1 80/1 ] ])。
  • 形状の不一致: 軸の長さが一致せず、どちらも1でない場合はエラーになります(例: [ 1 2 3 ] [ 10 20 ] *は長さ3と2を対応付けられないためエラー)。
  • スカラーの適用: スカラー値は軸を必要とせず、ベクトルがどう入れ子になっていても——不揃いなものも含め——すべての要素と組み合わさります。
  • 矩形条件: 2つのベクトル同士がブロードキャストできるのは、両方とも矩形(各軸の長さが揃っている)のときだけです。

その他の数値演算ワード

基本四則演算に加えて、次の数値演算ワードが用意されています。

  • 符号操作: ABS(絶対値)、NEG(符号反転)
  • 極値: MIN(最小値)、MAX(最大値)
  • 平方根: SQRT
  • 丸め処理: FLOOR(切り捨て)、ROUND(四捨五入)
  • 量子化: QUANTIZE——1/dの最も近い倍数に丸めます。ループ処理や反復計算での使用に適したワードです。反復計算と数値を参照。

決定論的擬似乱数 RANDOM

RANDOMもここにあり、他のすべてのワードと同じく1つの純粋関数です。7 3 RANDOMはシード7だけによって決まる、[0, 1)の範囲の厳密な有理数を3つ引きますが、これは毎回、どのセッションでも同じ3つを引きます。隠れた状態もホストのエントロピーもないため、厳密性や純粋性と矛盾するところは何もありません——ORDERと組み合わせれば決定論的なシャッフルになります(SEED N RANDOM ORDER)し、読みやすい分解能で値を引きたいときはQUANTIZEと組み合わせます。

実行時の値をブロックの中に入れる

ブロックはソースなので、プログラムの実行中に計算した値はその中には入っていません。MAPやFILTERはブロックだけしか取らないため、現実の疑問が生じます——実行時にしか分からない閾値でフィルタするにはどうすればよいのでしょうか。{ 5 LT }はリテラルの5と比較しますが、その数がプログラムの計算結果である場合、書くべき5はどこにもありません。

REFLECTは両方向でこれに答えます。欲しいブロックのトークンレコードを組み立て——実行時の値はSTRでその字句に変換し——REFLECTでブロックへ橋渡しして戻します。結果は普通のブロックであり、ブロックを取るすべてのワードがそれを受け入れます。

ここが、字句を持たない数が制約として現れる唯一の場所です。数値の文法が書けるのは整数と比の形だけなので、2 SQRTのような厳密な無理数にはSTRが生成できる綴りがなく、STRはそれに近い有理数を返すのではなく理由invalidEncodingを伴うNILを返します。埋め込みたい場合は、分解能を選んでそう明示してください——2 SQRT 10000 QUANTIZE STRは'7071/5000'になり、その近似はあなたのソースの中に、目に見える形で存在します。

CONDの節は、目に見えるスタックの上では実行されません。すべてのガード、そして発火した節の本体は、ちょうど1つの値——CONDがディスパッチしている値——だけを保持する隔離されたフレームの中で実行され、そこから戻ってくるのもちょうど1つの値、本体が終わったときに最上位にあるものだけです。これは、スタック全体を見るワードの本体やEXECとは異なります。5つの規則をまとめて見るにはブロックが見るものを参照してください。

DEFが検査すること、しないこと

DEFは本体を保存するだけで、その中の名前を解決しません。存在しないワードを呼び出す本体を持つ定義は受け入れられ、定義済みとして報告されます。失敗が表面化するのは、そのワードが最初に呼び出されたときです——{ TOTALL 1 } 'FOO' DEFは成功し、FOOを実行して初めてUnknown word: TOTALLが報告されます。

これは検査漏れではなく設計上の選択です。名前は呼び出し時に解決されます。これにより、あるワードが自分より後に定義される別のワードを呼び出すことができます——したがって2つのワードが互いを呼び合うこともでき、定義を依存関係に合わせて並べ替える必要は決してありません。

その代償として、本体の中の誤字は、何かがそれを呼び出すまで静かに潜んでいます。これを事前に検出できるのがヘッドレスCLIです——ajisai checkは何も実行せずにファイル中のすべての名前を解決し、未知のものを報告します。ajisai check --contractはさらに宣言されたワード契約も検証します。Playgroundにはこれに相当するものがありません——アプリの中では、ワードを呼び出すこと自体が検査になります。

ワードの管理

DELは、引用された名前でユーザー定義ワードを削除します。依存関係は追跡されており、他のワードが依存しているワードはまったく削除できません。したがって宙ぶらりんの参照は起こり得ません——先に依存している側を削除してください。

ワード名は大文字・小文字を区別しません(add10とADD10は同じワードです)。慣例としてAPPLY-GAINのような動詞-目的語の形に従います。名前がどのように定義と対応付けられるかは、辞書とワードの同一性で扱います。

値に名前を付ける

BINDで名前を与える

スタックは一度に1つの値しか手渡してくれませんが、書く価値のあるたいていの式は、1つの値を2回以上使います。残差は二乗誤差と勾配の両方に使われ、閾値は比較と報告の両方に使われ、座標の組は和と差の両方に使われます。KEEPはコピーしますが、それで十分に思えて実は違います——上のコピーから何かを導出すると、その結果は下のコピーの上に乗ってしまうので、2回目の使用が1回目の下に埋もれてしまいます。

代わりにBINDは値に名前を与えます。値と名前を取って両方を消費し、それ以降その名前がすなわちその値になります。好きなだけ、好きな順序で使えます。

反復計算と数値

厳密算術は、ループのコストを変えます。このリファレンスの他のすべての節はプログラムが何を意味するかについてですが、この節はそれを繰り返すことが何のコストを伴うかについてです。厳密性が見返りに何かを要求してくる、唯一の場所だからです。

コストはどこから来るのか

厳密な有理数は分子と分母の組として格納されており、分数と分数の積は分母同士の積になります。1回掛けるだけなら何も起きません。しかしループの中で掛け続ける——これはまさに勾配降下法、ニュートン法、k-means、べき乗法、その他あらゆる反復的手法がやっていることです——と、分母はステップを追うごとに大きくなります。何も失われず、何も近似されません。数はまったく正しいままです。ただ、その桁が記録しているのはその値がどう計算されたかであり、その履歴は回を追うごとに長くなります。

QUANTIZEは値を1/dの最も近い倍数に丸めるので、その分母はdの約数になり、それを超えて大きくなることは決してありません。1ステップにつき1回適用すれば、導出の履歴を捨てて値だけを保ちます。

QUANTIZEは、他の算術ワードと同様にベクトルに対して持ち上がる(リフトする)ので、パラメータベクトル全体を1回の呼び出しで量子化できます。dが1のときはちょうどROUNDと同じです。

閉じた形はループに勝る

反復法に手を伸ばす前に、その問題に閉じた形があるかどうかを確かめてください——厳密算術においては、それは単に速いだけでなく、種類の異なる答えになるからです。最小二乗法、有理数のペナルティを使うリッジ回帰、k近傍法、有理確率上のナイーブベイズ、ジニ分割による決定木、パーセプトロン、単体法は、いずれも反復を伴わない厳密な解を持ちます。そしてAjisaiは、係数を最も近い表現可能な浮動小数点数としてではなく、まさにその有理数として返します。529/532として返ってくるR²は言語の不備によるものではなく、それが答えなのです。

超越関数——指数関数、対数関数、任意のべき乗——は語彙にありません。それらに対する有理数の答えは存在せず、Ajisaiは正当化できない数を返さないからです。それらの上に組み立てられる手法(ロジスティック回帰、softmax、交差エントロピー、ガウス尤度)は、この言語が計算する範囲の外にあります。SQRTだけが、この言語が代数的数として厳密に構成する唯一の無理数です。

辞書とワードの同一性

2つの階層: CoreとUser

辞書には2つの階層があり、それがすべてです。Coreは65個の正準なワードを保持し、封印されています——Coreの名前を再定義したり削除したりすることはできません。Userは、あなたがDEFで定義するすべてを保持します。

この65個のワードは、36語のSemantic Kernelと29語のStandardワードに分かれます。Kernelのワードは、ある種類の値を組み立てたり観察したりするもの、あるいは何かを行う唯一の明示的な方法であるもの——コードブロックの実行、NILからの回復、辞書の変更、出力、コードとデータの間の橋渡し——です。Standardのワードは、頻出する発想に1つの固定された名前と契約を与えます——SUB、MIN、SORT、MAP、TRIMなど。この区分は、あるワードが設計の中のどこに位置するかを教えてくれるだけであり、それを使う方法には何も変えません。65個すべては同じ1つのフラットな辞書の中にある普通のCoreワードであり、平易な名前で参照でき、契約・例・エラー条件も同じです。各ワードの階層はWord Referenceに一覧があり、そのワードを調べたときにも表示されます。

ワードを調べる

カーソルをワードの上に置いてCtrl+Alt+Lを押すと、PlaygroundはOutput領域に辞書から答えます——Coreワードならそのリファレンス項目、自分で定義したワードならそのDEFを、どちらも同じように「読むための文章」として表示します(エディタに戻して編集する形ではありません)。これはプログラムが行うことではなく、エディタが行うことです——何も積まれず、何も消費されず、答えは値ではなく文章です。したがってプログラムがここで呼び出せるワードはありません。Reset(Ctrl+Alt+Enter)、Stack clear(Ctrl+Alt+S)、Editor clear(Ctrl+Alt+E)がショートカットのみで存在するほかの操作です——それぞれセッション全体、スタック、この入力欄のテキストを破棄します。これら4つはいずれも入力して実行したりプログラムから呼んだりできません——RESETやLOOKUPという名前のワードは、ほかの名前と同じ普通のワードです。

名前解決と再定義

名前はCoreかUserのどちらかで解決され、UserがCoreを覆い隠すことは決してありません。したがってワードの名前が、そのワードの住所のすべてです——修飾された形もなく、選ぶべき辞書もなく、裸の名前が曖昧になる余地もありません。名前は大文字・小文字を区別しないので、add10とADD10は同じワードです。

サンプルコード期待値注記
{ 10 ADD } 'ADD10' DEF 5 ADD10 15/1 定義済みのワードは、その名前で参照される。
{ 1 } 'ADD' DEF error Coreは封印されているので、Coreの名前を奪うことはできない。
{ 10 ADD } 'ADD10' DEF { 20 ADD } 'ADD10' DEF 5 ADD10 25/1 再定義は、唯一のUserエントリを束縛し直す——ただし他のワードがそれに依存している場合は、DEFが拒否する。

ワードの同一性

すべてのワードはコンテンツ同一性を持ちます——正規化された定義と、それが呼び出すワードたちの同一性にわたるダイジェストです。同じ同一性を持つ2つの定義は、名前が何であれ同じワードであり、定義を変更すると、それに依存するすべてのものの同一性が変わります。これが、DEFとDELが、他の何かがまだ参照しているワードを乱すことを拒否する理由です——依存しているのはワードに対してであって、綴りに対してではありません。

出力

PRINTは、スタック最上位の値を出力領域に書き出します。他のどのワードとも同様、既定ではオペランドを消費します。KEEPを付ければ、値はスタックにも残ります。Playgroundは常に最終的なスタックを表示するので、PRINTは結果を見るためではなく、出力チャンネルのためのものです。

引用符は表示上の便宜

文字列は、数値ベクトルと見分けられるように、スタック上ではシングルクォートで囲まれて表示されます('TEST')。この引用符はStack表示に属するものであり、値には属しません——PRINTは生のテキストを書き出すので、'TEST'はTESTとして出力されます。テキストの一部である引用符文字はそのまま保たれます(内容がT'ES'Tである文字列はT'ES'Tとして出力されます)。数と真偽値は、スタック上に現れるのとまったく同じ姿で出力されます。

同一性モデル

AjisaiではEQ、LT、GTEのような普通の比較ワードを書けますが、言語は舞台裏でいくつもの「同じか?」という問いを別々に保っています。

層利用者にとっての意味重要な理由
値の等価性これらは同じ数学的な値か?比較ワードが使うのはこれ。
構造的同一性内部で同じ方法で格納されているか?利用者からは観測できない。実装は表現を自由に最適化してよい。
表示上の等価性描画された2つの文字列は同じに見えるか?表示は人間の助けにはなるが、等価性の証明にはならない。
適合等価性実装は同じ観測結果を生むか?移植版が同じAjisai言語であることを示す方法。

比較ワードは最上位の層でのみ働きます——あらゆるAjisaiの値にわたって厳密かつ全域的であり、数学的な問いに答えます。それより下の層は値のモデルには関与しないので、表現や表示が比較の結果に影響することは決してありません。
